# Technical Requirements Document (TRD)

**Project Name:** DuskyMoon Productions Official Website  
**Version:** 1.0.0  
**Target Environment:** Production (Web)  
**Main Focus:** Technical SEO, Entity Resolution, and High Performance  

## 1. Technology Stack
* **Framework:** Next.js 14+ (using App Router for optimized Server-Side Rendering).
* **Language:** TypeScript / JavaScript (ES6+).
* **Styling:** Tailwind CSS (Utility-first styling for faster load times and zero CSS-blocking rendering).
* **Animations (Optional):** Framer Motion (for smooth, cinematic page transitions without heavy JS payload).
* **Package Manager:** `npm` or `pnpm`.
* **Version Control:** Git & GitHub.
* **Hosting/CI-CD:** Vercel (Native support for Next.js).

. SEO & Entity Resolution Implementation (The "Ninja Trick" Details)
3.1. Server-Side Metadata (layout.tsx)
Instead of standard React <Helmet>, Next.js Metadata API must be used to ensure bots read the data before page load.

TypeScript

3.2. Injecting Structured Data (JSON-LD)
The JSON-LD Organization schema from the PRD must be rendered as a server component to guarantee it is injected into the initial HTML payload.

TypeScript
// Inside src/app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  const schemaData = {
    "@context": "[https://schema.org](https://schema.org)",
    "@type": "RecordLabel",
    "name": "DuskyMoon Productions",
    "url": "https://[YOUR_DOMAIN].com",
    "founder": {
      "@type": "Person",
      "name": "Kxrn",
      "sameAs": "[https://kxrn.is-a.dev](https://kxrn.is-a.dev)"
    }
    // ... rest of the schema from Backend Schema Document
  };

  return (
    <html lang="en">
      <head>
        <script
          type="application/ld+json"
          dangerouslySetInnerHTML={{ __html: JSON.stringify(schemaData) }}
        />
      </head>
      <body>
        <Navbar/>
        {children}
        <Footer/>
      </body>
    </html>
  );
}
4. Performance & Optimization Targets
Googlebot prioritizes fast-loading websites. The build must strictly adhere to Core Web Vitals:

LCP (Largest Contentful Paint): < 2.5 seconds.

FID (First Input Delay): < 100 milliseconds.

CLS (Cumulative Layout Shift): < 0.1.

Asset Optimization: All images must use the Next.js <Image /> component (next/image) for automatic WebP conversion and lazy loading.

Lighthouse Target: 90+ across Performance, Accessibility, Best Practices, and SEO.

5. CI/CD & Deployment Pipeline
Version Control: All code commits to be pushed to origin/main on GitHub.

Auto-Build: Vercel is connected to the GitHub repo. Every push to main triggers an automatic npm run build.

Domain Mapping: Custom domain is routed via Vercel DNS. Vercel automatically handles SSL (HTTPS) provisioning.

Post-Deploy: Once live, the manual step is to test the live URL in Google's Rich Results Test tool to verify the JSON-LD payload, followed by a sitemap submission in Google Search Console.
